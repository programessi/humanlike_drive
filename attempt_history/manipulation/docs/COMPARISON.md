# 基线与当前操作方案的代码差异

| 部分 | baseline：`drive_baseline` | 当前：`wheel_manipulation` |
|---|---|---|
| 范围 | 包含视觉、路径控制、CARLA与机器人操作 | 独立机器人操作，内部生成目标序列 |
| Actor输入 | 单帧112维，含双手模拟接触力 | 8帧×122维，不含模拟接触力；训练critic另读54维特权信息 |
| 动作 | 26维：14个臂关节与12个手指关节参考修正 | 18维：12个手指修正、共同/差分相位、双腕径向/轴向修正 |
| 机械臂执行 | 轮角到关节角的IK查表及插值 | 连续微分IK，关节速度/加速度/位移约束 |
| 共同转动 | 基线角度反馈、圆弧参考及可选积分 | 明确的轮角前馈/反馈共同运动，加速度和相位余量约束 |
| 电机实现 | 显式计算PD力矩 | force-limited affine PD，implicitfast积分阻尼 |
| 环境与奖励 | 基线角度/速度、接触和残差惩罚 | 独立奖励、包络/漂移代理、保持判定与失败原因 |
| 训练 | 原SB3基线流程，既有视觉/驾驶权重 | 非对称actor/critic、独立仅手指消融、课程验证和部署actor导出 |
| 已测范围 | 多阶段基线实验，另有驾驶测试；不可等同实物范围 | 当前只完成±10°开发试验，尚未完成±30°验收 |

核心差异集中于两项目的`controller.py`、`env.py`、`train.py`、`evaluate.py`和场景。基线还拥有`vision.py`、`navigation.py`、`carla_bridge.py`；当前拥有`common/`中的观测、策略、连续IK、课程和验收工具。

此前复用的只是关节索引、名义电机参数、接触读取、渲染和驾驶室构建。现已提取为当前项目内部的`common/hardware.py`、`simulation.py`和`cockpit.py`，不再导入基线。它们保留相同机器人物理定义，但可以在两个项目中分别演进。

两项目源码、配置、场景、训练与评价产物完全分开；没有源码符号链接、运行时跨项目导入或共享可变配置。它们可以使用同一个已安装Python环境和同一个外部Unitree模型，这是明确的外部依赖，不是相互依赖。
