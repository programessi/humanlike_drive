# 腕手教师接口 v2（R0 冻结）

版本 `structured-wrist-teacher-v2-relative-strict`。仅兼容旧腕手教师的张量布局与动作含义；参考零点、负载和安全条件发生变化，因此权重作为初始化，不继承成绩。旧 26 维关节策略不兼容。

## 输入

actor 为 float32[152]，索引为 Python 半开区间。教师另读 privileged[54]，编码成 16 维；部署学生尚未训练。

| 索引 | 内容与尺度 |
| --- | --- |
| 0:26 | 14 个臂主动关节＋12 个手驱动位置，rad |
| 26:52 | 主动关节估计速度 / 5 rad/s；差分低通 |
| 52:78 | 已命令关节目标减测量值 / 0.15 rad |
| 78:102 | 上次策略动作，归一化值 |
| 102:120 | 两腕相对轮轴的位置 / 0.2 m，以及姿态旋转矩阵前两列 |
| 120:122 | 累计轮角 rad、估计轮速 rad/s |
| 122:128 | 0、0.1、…、0.5 秒参考轮角相对测量轮角的误差 / 10° |
| 128 | 当前参考轮速 / 20°/s |
| 129:140 | 轮轴中心 / 0.8 m、轮轴基坐标前两列、半径 / 0.14 m、轮辋粗细 / 0.014 m |
| 140:152 | 左右腕命令位置误差 / 0.02 m、旋转向量误差 / 0.2 rad |

特权量：26 个主动关节驱动输出比例、12 个从动关节位置、两手接触力/100、峰值与异常负载/100、两手包围与滑移代理、轮轴阻尼/摩擦/质量、平均 PD 比例、动作/观测延迟和轮辋摩擦，共54维。仅教师可用；actor 基础帧不读取接触或从动指节真值。教师 actor 通过特权隐变量间接使用真值，不称为已部署策略。

## 输出和执行

动作 float32[24]：0:6 左腕、6:12 右腕，各为切向/径向/轴向速度与轮轴坐标中三轴角速度；12:18 左手、18:24 右手各六驱动位置。输入裁剪到[-1,1]。

腕平移满幅0.05 m/s、旋转满幅40°/s；0.1秒一阶滤波。腕零动作停止积分，不是松手。手动作通过分段线性映射覆盖原生关节上下限：零动作对应nominal_closed标定抓握，负/正动作分别趋近下/上限；零动作不是保持实测角度。实现见 `legacy/exploration/controller.py::hand_targets`，不能与从动关节混淆。

策略20Hz、机器人目标/QP50Hz、物理500Hz。腕位置领先实测最多0.012m，朝向领先10°；臂目标领先5°、命令留3°边界，实测硬门槛2°。臂速度1rad/s、加速度4rad/s²；手1.5rad/s、8rad/s²。QP处理关节边界、几何防撞和冗余姿态；每物理步独立检查实测安全。记录QP失败、约束激活、工作域裁剪及腕任务误差。

参考由预先生成的外部时间序列推进，不读取误差改变速度，也不冻结时钟。腕执行层不含轮角误差伺服、换手状态机或隐藏轮轴驱动。回正弹簧始终指向固定机械零位，准备结束时的参考起点不改变弹簧零点。

奖励复用本地 `legacy/regrasp/env.py::_reward`，包括角度、速度、支持、余量、动作平滑及负载项；R1关闭朝向与恢复课程引导。全部乘0.05，事件终止基础惩罚10对应缩放后0.5；TensorBoard同时记录原始项和缩放项。旧KL自适应未移植，本次使用其最终学习率1e-5固定继续，单独记录这一差异。

## R2 v3：手指增量目标（2026-10-27）

版本 `structured-wrist-teacher-v3-incremental-hand`，网络仍152/54输入、24输出。前12维腕动作不变；后12维改为归一化手驱动目标增量：20Hz满幅0.03rad，实际50Hz目标更新时按周期换算。此处“leaky”是实现选项名，不能把v2绝对手目标权重直接当作v3策略执行。

```text
r = robot_dt / 0.05
q_hand_desired = q_hand_measured
                 + alpha**r * (q_hand_cmd_old - q_hand_measured)
                 + 0.03 * r * filtered_action_hand
```

初次学习取alpha=0.995/20Hz（约10秒泄漏时间常数）；另保留0.95和1.0冻结对照。之后仍经过原生位置限位、速度/加速度约束与命令领先限制。零动作不再跳到nominal_closed；已有q和motor_target−q使目标积分状态可观测，不依赖隐藏reset锚点。

v2的joint_lead在当前实现中同时约束臂和手（5°）；单手初始示例中3/6个支持手驱动的绝对目标超出实测5°以上。局部动作可能被映射到相同执行目标。冻结权重诊断中，固定初态手驱动目标将左保持峰值2.402°降至0.143°，只置零腕动作仍2.402°。该诊断只定位原因，不是主线锁手方法。

初始化明确迁移：保留腕输出、编码器、actor主体及critic；将手输出头12行置零，并清除对应Adam行状态，保持原log_std。所有手输出参数仍可训练，运行中没有锁手。该首轮适配包含动作语义与必要初始化，不宣称单因素奖励消融；首轮奖励仍用4°宽度原配置。后续σ=2°精修另有单因素配置和验收记录，当前R2仍未通过。

无训练的v3探针改善了保持，但在部分右手负载运动中失去抓握。因此还必须通过PPO学习维持预紧力，不能用新接口的初始保持成绩冒充R2完成。所有R1双手任务、左右单手任务及独立验收均须在v3下重新检查。

R0–R2当前RMSE按20Hz控制采样统计；保持和末段峰值按500Hz物理步检测，诊断同时报告全程峰值。初态手闭合与settling抖动在动力学随机化强度0时仍存在。

## R2修复 v4：臂手独立目标领先量（2026-10-27）

版本 `structured-wrist-teacher-v4-separate-hand-lead`。输入、网络、24维动作、泄漏积分和各控制频率沿用v3，仅增加显式执行配置 `hand_joint_lead_rad`。默认`None`保持v3行为；本次配对实验为0.15rad，机械臂名义领先量仍5°，命令/实测关节余量、速度、加速度与执行器力矩上限均不变。领先量约束的是目标与实测之差，不是策略每步可以运动的角度；与加速度可行性冲突时原有边界算法可能放松领先约束，不能把它称为绝对力矩上限。

准备阶段保持原流程，新的领先量只影响策略执行阶段。手指仍可自主开合，并未固定初态手指目标或屏蔽腕部动作。v3到v4不改动作语义，因此保留全部策略、探索尺度和优化器状态，不重新清零手输出头；行为变化必须按新接口重新评价，不能继承v3合格成绩。

配置、训练开发评价与独立评价均显式传递该字段。手动评价v4模型时省略`--hand-mode`以读取模型旁的`config.json`，或同时显式指定`--hand-mode leaky --hand-alpha .995 --hand-lead-rad .15`；不能以v3的5°手指限制评价v4成绩。冻结策略诊断与正式v4执行的准备初态、观测、动作、奖励和物理轨迹已做等价测试。当前v4仍属研发实验，不代表R2通过。
