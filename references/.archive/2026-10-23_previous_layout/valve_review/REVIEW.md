# Inspire 六驱动手操作方向盘：相近任务与方法调研

调研日期：2026-10-04。硬件条件：H1-2 双臂、用户现有 Inspire 手；每手六个独立驱动，部分指节联动。现有手的具体型号、固件与力反馈接口还需核对，不能仅凭“Inspire 六驱动”认定与 RH56DFX 完全一致。

本次只做文献与公开代码审阅，未修改驾驶控制、启动训练或执行硬件指令。当前驾驶方案继续作为“基线”保留。

## 1. 结论与检索边界

用户任务可以归入 **power-grasp manipulation of articulated objects with contact-mode changes**：包络抓握有固定机械关节的物体，持续跟踪物体的运动，并在必要时切换接触。需要同时检索 valve turning、bimanual manipulation、articulated-object manipulation、constrained manipulation、regrasp、hybrid force/position control。

本次核验的工作里，尚未找到同时满足以下条件的完整实例：**Inspire 六驱动手、大半径圆环、双臂包络抓握、长期带时间要求的角度序列跟踪、交替换握**。这只是本次检索结果，不是“从未有人做过”，也不能单独作为论文新颖性证据。

有价值的参考分成三个互补方向：

1. **任务与受力结构**：COMAN 双臂阀门操作，阶段划分与双臂顺应控制。
2. **硬件与 RL 环境**：RH56DFX 标定/建模，以及 DexArt 对关节物体的抓握转动任务。
3. **长期操作与重抓**：CyberDemo 的真实多圈小阀门旋转，以及 DIPS 对接触模式的显式规划。

## 3. 优先精读的工作

### 3.1 COMAN：双臂阀门任务如何分阶段、处理受力

**A manipulation framework for compliant humanoid COMAN: Application to a valve turning task**，2014。

- [论文 DOI](https://doi.org/10.1109/HUMANOIDS.2014.7041434)
- [HAL 公开记录](https://hal.science/hal-04307553)

摘要明确给出四个操作原语：**Reach → Grasp → Rotate → Disengage**。每个阶段对应不同阻抗配置；旋转阶段使用双臂阻抗规划与控制，既建立稳定接触，又产生足以克服阀门摩擦的转矩。摘要报告 Gazebo 和真实实验。

可借鉴的核心：控制器必须区分“建立抓握”“承载转动”“卸载释放”，并考虑两臂通过同一个刚性物体形成的相互作用。只让两个腕部各自追位置，可能产生互相对抗的内力。

**核验限制**：本次获得并核对了摘要，HAL API 给出全文文件地址，但下载返回网站验证 HTML，未取得 PDF。因此没有确认手的机构、阀门半径、是否完全包络、重抓次数、完整控制方程或开源实现。不能将这些细节写成已验证事实。

### 3.2 Inspire RH56DFX：六驱动耦合手的实际能力与接口

**Characterization, Analytical Planning, and Hybrid Force Control for the Inspire RH56DFX Hand**，2026 预印本，Xuan Tan、William Xie、Nikolaus Correll。

- [全文](https://arxiv.org/abs/2603.08988)
- [公开代码](https://github.com/correlllab/rh56_controller)
- [H1-2 文档](https://github.com/correlllab/rh56_controller/blob/main/docs/h12.md)

全文处理了六驱动、耦合指节与拇指工作空间；通过测力计将原始 0–1000 负载反馈标定为力。论文实验中命令到传感响应约 66 ms，高速接触产生明显力超调；采用快速接近、低速建立接触和力反馈闭合。真实验证包括插孔与 15 类物体抓取，报告成功率分别为 65% 和 87%。这些数据对应论文的实验设置，不是当前手的保证值。

仓库提供手模型、抓握几何规划、H1-2 仿真选项及可选 ROS2 接口。但 H1-2 抓握可视化文档描述的是 PINK IK 和直接写仿真关节位置，**不能将可视化当作动力学下稳定抓握的验证**。仓库 force-control 文档的臂顺应控制流程面向 UR5，也不能据此认定 H1-2 已具有相同闭环。

对当前项目最实用的启发：以真实驱动数建动作空间，验证联动几何、拇指包围能力、轮辋截面与掌指接触；测试实际位置/速度/负载读数及延迟。Inspire 原始负载信号需要标定，不能直接替代当前 MuJoCo 的“每手接触力模长求和”。后者既不是腕部六维力矩，也没有保留各接触点的方向。

### 3.3 DexArt：可读、可复用的抓握转动 RL 任务

**DexArt: Benchmarking Generalizable Dexterous Manipulation with Articulated Objects**，2023。

- [全文](https://arxiv.org/abs/2305.05706)
- [代码](https://github.com/Kami-code/dexart-release)
- [水龙头 RL 环境，固定版本](https://github.com/Kami-code/dexart-release/blob/d6ab75e1a0b81384d1ac918cbfd4d97b1f230149/dexart/env/rl_env/faucet_env.py)
- [动作控制实现，固定版本](https://github.com/Kami-code/dexart-release/blob/d6ab75e1a0b81384d1ac918cbfd4d97b1f230149/dexart/env/rl_env/base.py)

任务：抓牢水龙头把手，然后转动约 90°。物体具有实际 revolute joint，不是自由空间画圆。机器人是 xArm6 + Allegro 16 自由度。

论文使用 PPO，PointNet 编码物体/机器人点云，并融合本体状态。22 维动作包括 **掌部六维线速度/角速度 + 16 个手指关节位置目标**。代码通过 Jacobian 逆解将末端速度变成臂关节速度，积分得到位置参考，再使用 PD。因此它是学习策略结合基础运动学控制，不能称为“没有 IK 的纯关节 RL”。

环境代码按接近、抓握、转动给奖励：离把手较远时鼓励接近；要求掌部与至少两根手指接触；抓握建立后奖励转角，并惩罚臂部碰撞、关节速度与笛卡尔控制误差。代码的 `horizon=250`，超过约 1.5 rad 且保持抓握可以提前成功结束。

这份实现适合借鉴阶段奖励、物体关节建模和动作接口。但接触奖励和完成一次开阀，不能直接替代长时间稳定包络抓握指标。接触判断来自仿真，不能默认真实硬件能够获得同样的二值信号。原论文不提供其水龙头策略真实部署的证据。

### 3.4 CyberDemo：真实多圈旋转与示教数据增强

**CyberDemo: Augmenting Simulated Human Demonstration for Real-World Dexterous Manipulation**，2024。

- [全文](https://arxiv.org/abs/2402.14795)
- [项目与视频](https://cyber-demo.github.io/)
- [项目链接的代码仓库](https://github.com/wang59695487/hand_teleop_real_sim_mix_adr)

Rotate 任务是固定底座、多爪阀门经 revolute joint 旋转 **720°**；用三爪阀门收集数据，再测试四爪、五爪形状。真实机器人为 xArm6 + Allegro。策略读取 RGB 与本体状态，学习遥操作动作序列；使用动作分块、时间聚合和仿真数据增强。全文采集接口描述为六维末端笛卡尔速度与手指关节位置，在几何增强推导中以离散位姿增量描述动作。

有用之处是实际多圈接触操作、形状/位置/视觉条件增强及 sim2real。它没有验证六驱动手对大圆环的包络抓握，也没有要求按外部时间序列逐点达到角度。不能把 720° 完成任务直接等同于驾驶中的低误差动态跟踪。

### 3.5 DIPS：把释放、保持和重抓当作不同接触模式

**Diffusion-Informed Probabilistic Contact Search for Multi-Finger Manipulation**，2024。

- [全文](https://arxiv.org/abs/2410.00841)

核心是显式描述哪些手指保持接触、哪些手指释放并前往新位置。使用带接触、运动学、摩擦与避碰约束的 CSVTO 生成轨迹数据，训练模式条件 diffusion 模型，再用 A* 搜索接触模式序列；执行过程中重新规划。

螺丝刀仿真中底部固定但允许转动。真实实验有重抓，并需要调整力初始化以弥补模型误差。它关注什么时候重抓、重抓谁，以及剩余接触能否支持物体。对双手方向盘，可以借鉴“先建立接替抓握，再卸载另一手”的模式规划思想；从手指模式推广到双臂并不是现成结论。

它是学习与约束规划结合的方法，不是单个 diffusion 网络直接保证接触约束。论文报告真实螺丝刀 A* 单次规划平均约 10.1 s，CSVTO 每步优化约 16.1 s；不能按原样作为 50 Hz 方向盘伺服。若借鉴，优先考虑慢速接触模式规划，快速执行由另一个控制器承担。本次未核实官方开源仓库。

## 4. 其他参考与容易混淆的地方

### DClaw / ROBEL

- [2018 论文](https://arxiv.org/abs/1810.06045)
- [ROBEL](https://github.com/google-research/robel)
- [目标角度任务代码，固定版本](https://github.com/google-research/robel/blob/5b0fd3704629931712c6e0f7268ace1c2154dc83/robel/dclaw/turn.py)

三指九驱动的小型阀门操作，原论文研究模型自由强化学习和示教增强，包含真实学习。ROBEL 提供目标角度误差、上一动作、手指位置等观测；观测字典另有速度等信息，但不能认定全部字典项都被默认拼入策略。读取的版本默认选择 `claw_qpos, object_x, object_y, last_action, target_error`。

动作控制手指；angle error 被包裹到 [-π, π]。这适用于周期角度到达任务。若方向盘任务需要记录多圈进展，应另外保留不折返的角度/圈数，不能仅用 sin/cos 与最短角度差区分目标。ROBEL 默认成功阈值 0.1 rad 约 5.7°，不是高精度跟踪保证。ROBEL 与原论文的奖励阈值也不应混写。

### RBO Hand 2

- [2016 全文](https://arxiv.org/abs/1603.06348)
- [论文视频](https://youtu.be/XyZFkJWu0Q0)

七气动通道软手，物体中心示教结合轨迹 RL 和 guided policy search。阀门实际是蓝色杠杆型小气阀；回合内臂固定，主要靠不同手指推动。它证明少量驱动结合机械柔顺可以学习接触操作，但不是大半径轮辋的包络旋转。软手的被动顺应不能直接搬到电驱动 Inspire。

### Atlas、Musashi 与拟人重定向

- [Atlas autonomous valve turning，2014](https://doi.org/10.1109/HUMANOIDS.2014.7041407)：摘要描述双臂掌部、非抓持操作与顺应控制，不能作为包络抓握证据；本次仅核验摘要。
- [Musashi driving，2020](https://doi.org/10.1109/MRA.2020.2987805)：真实驾驶和手部释放顺序相关，但肌腱驱动结构与按压/推拉式方向盘操作不同于当前包络手。
- [humanoid-dexart-retarget](https://github.com/gtziafas/humanoid-dexart-retarget)：README 提供 G1 + Inspire RH56DFX 的手物交互重定向；可参考拟人示教生成。目前核验的是项目说明，不能认定其已实现阀门 RL、动力学稳定抓握或真实部署。

## 5. 对当前研究范式的判断

### 任务难点来自闭合接触链，不仅来自圆弧形状

物体固定轴意味着手不能随意沿六维空间运动。双手抓住同一个方向盘后，两臂、双手和轮轴形成闭合链。轮轴会通过反力阻止不允许的运动，但这种几何限制 **不会自动限制接触力**。因此“仿真中轮心没有偏移”不等于“没有危险内力”。即使腕部参考在理想圆弧上，模型误差、腕姿态误差、关节插值、手指联动与滑移仍会改变接触。

可优先区分：沿轮辋切向的运动用于产生转动；法向及轴向误差关系到接触压力和约束反力；双臂内力则关系到是否相互对抗。具体阻抗方向与增益必须结合接触和实际硬件辨识，不能把一个固定经验设置直接当作安全保证。

### RL 是合理候选，但不需要让一个策略同时学完所有问题

DexArt 与 DClaw 说明 RL 可以用于关节物体操作。当前基线也已经展示有价值的驾驶能力。问题不是“RL 范式必然不行”，而是当前短回合、预抓握、固定接触假设是否足以覆盖长期抓握、反向、漂移和换握。

若后续仍希望以 RL 为主，应先明确动作与信息边界：

- 末端速度 + 六驱动手目标可借鉴 DexArt，但仍包含运动学控制，不应称为 IK-free。
- 直接输出臂关节与六驱动手目标可以做无 IK 策略；它需要自行学会沿约束运动与协调双臂，不能因没有 IK 就认为更可靠。
- 有界参考残差、夹握力/闭合程度调节也是合法 RL 设计，应如实称为残差策略。
- Actor 只读取能在真机获取的本体状态、轮角测量、目标与其历史、经验证的手反馈；仿真接触点/力可用于 critic 或奖励，不能悄悄作为部署 actor 的必需输入。
- 若存在传感延迟、滑移等部分可观测因素，可比较历史堆叠或 GRU 与 MLP；记忆网络本身不会修复不连续参考或错误接触模型。

以上是下一阶段设计建议，没有在本次调研中实现或比较这些模型。

## 6. 应先建立怎样的操作 benchmark

按阶段形成独立测试，而非先更换驾驶路径点算法：

| 阶段 | 目标 | 需要记录的指标 |
|---|---|---|
| 包络抓握 | 手从未抓状态接近轮辋、闭合，保持不同负载 | 持续时间、脱离率、相对滑移、峰值接触/关节负载 |
| 单次转动 | 随机角度目标，含顺逆方向和不同阻力 | 到达误差、保持误差、耗时、约束反力 |
| 动态跟踪 | 带时间戳的角度序列，含停留、反向、快慢变化 | RMSE、最大误差、延迟、5/10 分钟稳定率、漂移趋势 |
| 双手换握 | 接替手建立并承载抓握，另一手卸载释放、重抓 | 承载连续性、换握成功率、冲击、臂碰撞与内力 |
| 泛化与拟人 | 半径/轮辋厚度/位置/摩擦/延迟变化，示教姿态 | 未见条件成功率，关节平滑性，人体动作相似度 |

模拟轮轴应由机器人接触驱动；环境不得直接把轮角写到目标来代替操作。方向盘本身可设实际的转角范围，阀门多圈任务可另设连续关节；两者不要混用目标与评价规则。

训练可从短回合逐步增加持续时间、阻力变化、反向与换握；测试必须有独立长回合。奖励需要区分稳定包络与瞬时触碰。对于损坏风险，峰值约束反力、异常关节负载和碰撞应有明确测量/终止标准，不能只依赖一个平滑动作奖励。

未来的拟人性可以来自重定向示教或动作先验，但必须检查示教在实际手指联动、接触和臂工作空间下是否可行。驾驶 diffusion 路径点上游可以后接，它不能解决抓握滑移或两臂内力。
