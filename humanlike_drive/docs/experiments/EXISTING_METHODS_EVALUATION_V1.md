# 第二层协议：已有方法的筛选、适配与能力边界

版本v1.1，2026-11-07。状态：待执行。对应[研究计划v4.1](../plans/RESEARCH_PLAN.md)。本协议确定选择与评价过程，不预先认定任何方法会失败，也不宣称已找到方向盘任务SOTA。

## 1. 进入正式比较前的条件

第一层已为待比较范围提供代表性完整动态往返、声明负载和统一评价。当前优先9点／3点初态、掌心摩擦主驱、两手上半圆操作与0—180°；只验证部分范围时，可以开展同范围比较，明确不代表完整T1。无需等待360°／540°；更大角度按设备与物理证据另行进入。尚无物理证据的部分只作探索，不把学习失败解释为方法局限。

观测、动作、执行器内部状态、参考时钟、失败条件和训练／开发／留出划分均有版本。真实接口暂不可用时，明确部署观测是待R0确认的假设，后续字段变化需重评。

## 2. 为每个候选建立适配卡

| 字段 | 必须写清楚 |
| --- | --- |
| 原工作与来源 | 论文、官方仓库、commit、环境／权重及许可；未核实项标未知 |
| 原任务差异 | 固定轴或自由物体、单手或双手、角度或速度目标、是否已有抓握 |
| 观测 | actor／critic／部署分别可见什么，是否需要图像、触觉、完整指节反馈 |
| 动作与执行 | 输出维度、位置／变化率／力矩、低层控制器、频率、mimic假设 |
| 数据和参考 | 所需专家、人类或真实数据，采集方式、覆盖与来源 |
| 可直接复用 | 算法、网络、缓冲／蒸馏代码、损失、训练与评价基础设施 |
| 必须适配 | 几何、双手接口、被动轮轴、目标、终止、观测、数据与奖励 |
| 合理预算 | 原公开预算、当前吞吐、开发调参范围和正式训练预算 |
| 适配资格检查 | 小任务、已知轨迹或原任务片段上的闭环正确性与学习曲线 |
| 选择理由 | 为什么代表一个方法族，为什么选它而不是全部实现 |

原公开权重跨机器人、动作维度或传感器时一般不能直接执行。没有权重、没有代码、仅借范式分别标注，不把新实现称为直接复现。

## 3. 候选路线与实施顺序

1. 调研固定轴旋转、双手相对协调、参考跟踪和长时序衔接工作，完成适配卡。
2. 先选一条有可靠实现的目标条件RL做局部资格检查；教师信息条件预先确定。
3. 新专家数据具有足够任务覆盖后，在ACT／Diffusion Policy中选一个做直接模仿。使用状态输入等适配时，说明与原视觉版本差别。
4. 选参考／示范辅助RL进行比较；[B0草案](../plans/BASELINE_IMPLEMENTATION_V1.md)只是此类中的候选，也可依据开源实现选择更合适的路线。
5. 在正式运行前确定最终2—3条代表性方法及比较范围，不同时展开全部框架。数据不足或实现未验证的方法标未就绪，不纳入“范式失败”统计。

主线比较可以由局部扩大到完整任务，但最终结论必须基于完整执行。只会局部跟踪的模型，不因平均误差小而算完成接力。

## 4. 两种信息条件分开评价

| 条件 | 比较方式 |
| --- | --- |
| 仿真特权／oracle诊断 | 在匹配的actor特权和执行边界下比较，区分有无示范及不同训练成本 |
| 部署反馈 | 相同可用关节／轮角／腕轮关系和指令预览；记忆、推理频率与成本分别记录 |

不把读取接触真值的教师与没有接触反馈的BC学生直接排名。critic特权也要记录。若某方法天然需要额外触觉，给所有方法相同条件或单独列传感收益，不作为同观测比较。

工程控制可作物理存在性参照，其脚本阶段、接触真值和规划成本要明确；信息不同的工程控制不是部署学习算法的公平性能上限。

## 5. 数据与预算的公平性

第一层成功轨迹只是仿真工程专家候选；须核对观测、实际命令标签、反馈与控制器内部状态，验证动作可重放性、物理合法性和对应范围任务完整性后再纳入。专家示范必须来自新场景和有效动态执行，按完整轨迹／会话划分，保存20 Hz实际命令及执行反馈；不从qpos差分冒充动作标签，不自动混入旧90°轨迹。

模仿任务的数据需覆盖相应行为和后续接管。如果只提供短片段却评价未覆盖长序列，必须说明这是组合外推测试，而非直接证明模仿范式无效。

分别报告专家生成／采集、BC或其它预训练、RL环境交互、调参、推理和真实适配成本。可以在共享专家数据的方法间匹配数据，在RL之间匹配交互预算；方法族之间采用成本—性能表，不笼统宣称完全同预算。

任务、设备、负载、执行约束和评价器固定。不同动作表达若引入IK或贴合控制器，应记录其信息和计算；判断收益来自算法还是执行表示，必要时补匹配控制器的比较。

## 6. 从资格检查到正式运行

资格检查至少包括：单位／符号、动作限速、目标积分、状态和命令区分、episode终止、历史／序列边界、无轮轴辅助、无接触真值泄漏及原限位／mimic。

先确认方法能在简单局部任务学习；若无学习趋势，先检查实现、奖励尺度、数据、优化与模型容量。允许合理开发调参，保存每次变更，不能只跑默认设置就报告算法不行。

开发完成后，冻结任务矩阵、预算、随机种子、数据划分、推理设置、评价次数和检查点选择。正式随机训练至少3个种子，成功率另列评价样本数与不确定性。当前尚未测新环境吞吐，不虚填训练小时或统一总步数。

冻结清单未完成前，结果只算开发，不用于支持最终优越性。

## 7. 评价与失败原因分层

完整任务记录去程、保持、返回与混合序列；轮角任务时钟不停，接管不重置状态。角度精度、碰撞、负载、失握和人工干预独立检查。报告任务成功、有效进度、局部操作、连续交接、回正、漂移与成本。

每个主要失败至少记录时刻、轮角、抓点／腕姿、任务指令、实际接触、负载、执行目标和异常。先分类型，再提出原因：

| 类型 | 优先核查 | 不应直接得出的结论 |
| --- | --- | --- |
| 几何／执行 | 能否用第一层控制从同一状态完成，是否饱和或碰撞 | 网络缺少规划能力 |
| 数据／参考 | 是否有同类起点、反向、接管后操作，标注是否矛盾 | BC／参考范式不适用 |
| 优化／实现 | 学习曲线、奖励尺度、目标处理和合理预算 | 所有RL都无法完成 |
| 观测／迁移 | oracle与部署观测差距、反馈延迟、历史可观测性 | 只需换更大网络 |
| 衔接／决策候选问题 | 前次末态、接近路线、后续操作与重复接力 | 已经证明某个新模块必要 |

诊断可做局部接续、观测对齐、数据补齐等实验，但每次改动均另记版本，保留原结果。

## 8. 第二层交付和第三层入口

交付适配卡、全部调参／成本、冻结任务、完整视频、模型和来源、各信息条件的结果表及失败清单。

只有在物理、数据、实现和合理优化已排查后，仍然存在重要且可重复的不足，才填写第三层的问题说明：现象、竞争解释、已有证据、需要的新机制及最小诊断实验。不能把“全部失败”直接当作突破依据。

已有方法满足要求时，诚实记录任务在声明范围内已有效解决，评估系统与经验价值。本文不要求必须进入新算法阶段。
