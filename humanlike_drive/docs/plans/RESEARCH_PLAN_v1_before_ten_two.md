# Humanlike Drive 研究与实施计划

更新日期：2026-11-06。本文是新项目的执行初版；其中的网络规模、采样数量和验收门槛是计划值，不代表已经实现或验证。

本计划同时包含仿真和实物两条工作线。仿真承担主要策略训练与大规模对照；实物从项目开始就参与接口确定、负载测量、分阶段技能验证和最终论文实验。

当前起点已更新：放下旧场景和旧数据，从本机原始 H1-2 / Inspire 模型和 Logitech G29 URDF／CAD 重建坐姿驾驶室。当前可查看的场景、四种基础抓握及验证范围见[场景说明](../SCENE_LOGITECH_G29.md)。先检查布局与接触，不直接启动训练。

## 1. 要完成什么

让固定上半身的人形机器人，用双臂和灵巧手控制被动方向盘。输入是带时间要求的累计轮角指令；一个策略负责转动、保持、释放、接管、重抓和受控回正。

论文重点研究：**在方向盘持续存在回正负载、手臂活动范围有限时，如何借助人类交互参考，让机器人在换握过程中继续可靠承载和跟踪。**

任务分两层推进：

- **0–180°：**学习连续角度目标，覆盖去程、停留和返回。
- **360°、540°：**先完成少数典型的大角度完整模板，再研究更自由的指令变化。到达这些终点之前，整段运动仍须连续闭环跟踪。

第一版从有效的初始抓握开始，不同时研究道路感知、驾驶规划、行走和从任意位置抓取方向盘。初始抓握作为单独准备过程记录。90°、180°等用于安排课程，不写成执行时必须换手的阈值。

## 2. 采用什么范式

主线采用：**实物测量与人类参考 → 仿真强化学习与历史学生 → 分阶段实物验证 → 根据真实差异进行适配。**

```text
实物测量反馈、延迟与负载；采集人类交互示范
                  ↓
在仿真中训练教师：学习跟踪、承载与换握
                  ↓
让学生在自己的执行状态上学习教师动作
                  ↓
得到只使用实际可获取信息的统一历史策略
                  ↓
在实物上逐级验证：保持、单手承载、接管、完整往返
                  ↓
用真实差异修正仿真或补充真实示范，再训练与复评
```

这里的“教师”可以读取仿真中的接触、负载等额外信息；“学生”只能读取部署时能获得的反馈。学生使用 DAgger：先自己执行，再让教师对学生实际到达的状态给出动作标签，补充训练数据。

BC 用于可选的初始化和必要的动作蒸馏，不要求必须先做 BC。ACT、Diffusion Policy 作为同数据条件下的对照。第一版不加入 VLA，也不同时实现世界模型。

人类示范提供交互参考，机器人实物数据提供执行与动力学证据，二者分别记录。仿真DAgger的教师标签不直接套用到未准确重建的实物状态。

## 3. 重新建立基础，保留历史经验

| 已有资产 | 新项目中的用途 |
| --- | --- |
| 旧场景与旧抓握数据 | 不进入新环境；用原始 H1-2、G29 CAD 和新生成的抓握重新建立基础 |
| 旧腕手动作接口、IK/QP、有限执行器 | 参考设计与失败教训，在新几何和限位下重新验证，不默认可用 |
| 轮角、停止保持、接触、关节余量等评价经验 | 在新项目独立实现评价接口 |
| v121 的90°／180°有限范围结果 | 只作为历史证据；若以后比较，须适配新场景并重新运行 |
| 旧物理专家与成功策略 | 不直接作为当前专家；先在新场景重新建立可行的显式控制与新数据 |
| 旧 PPO／GRU 的失败记录 | 用来安排诊断，不能据此断定某种算法不可行 |

v121 是监督结构化混合策略，不是普通 PPO 训练成功的模型，不能直接恢复成 PPO 继续训练。新场景改变了轮盘尺寸、转轴、坐姿与接触几何，旧能力不能视为新环境已验证的能力。新项目运行不依赖导入旧项目源码，不导入旧场景、旧抓握快照或旧数据集。

## 4. 第一版方法怎么实现

### 4.1 人类参考：记录关系，不要求复制人的关节角

先采集一个小样本，建议从20段完整往返开始，正反方向均有，包含保持、释放、接管和回正。先覆盖180°附近的交接行为，不为凑数量采集大量重复小角度动作。

每段至少记录同步视频、方向盘角度和双腕相对方向盘的位姿；标注接触区域，以及谁在释放、接管、重抓。不能可靠观察到的接触标为未知，不能从视频直接生成“真实承载力矩”标签。

若当前无法可靠采集三维腕姿，先用视频整理交互顺序，再用仿真专家构造对应的可行参考；记录其合成来源。只有后续加入真实人类数据验证后，才主张方法利用了人类动作证据。

### 4.2 学习目标：跟踪任务优先，参考允许调整

教师使用 PPO 起步。奖励分四组，分别记录数值与加权贡献：

| 目标 | 具体衡量什么 |
| --- | --- |
| 角度跟踪 | 运动误差、轮速误差、停止保持误差 |
| 交互参考 | 双腕相对姿态、接触区域、合理的交接关系 |
| 承载连续 | 有回正负载时，接触产生的轮轴力矩是否支持任务执行 |
| 物理约束 | 关节余量、非法碰撞、过大接触力、动作突变 |

第一项研究对比是：**严格按参考时间跟踪双手动作，和允许交接片段内提前／延后、允许局部姿态变化，哪一种更稳。**

第一版按标注片段设置参考匹配窗口，限制片段按顺序推进，避免随意跳到容易得分的参考状态。窗口宽度、姿态容差和推进规则在试验前写入协议。两组使用相同的参考来源和任务奖励，区别仅在匹配方式。

外部角度参考始终按原定时间推进。调整交互参考不能暂停任务时钟，也不能由执行器暗中补上角度控制。不能用“换手次数更多”作为收益，也不要求双手始终紧握。

### 4.3 策略：先实现一个适中的循环网络

部署输入包括：双臂关节状态、实际可读取的手驱动反馈、双腕相对位姿、上步动作、必要的执行器内部状态、累计轮角与轮速、当前角度误差及有限预览。累计轮角不取模，不能把180°、360°、540°混成同一状态。

初版计划使用 MLP 编码器、GRU128 和双腕／双手输出头；先考虑24维腕手接口，经 IK/QP 和有限执行器实现，须在新场景重新验证可行性。当前查看器直接控制14个手臂关节和12个手驱动，共26个执行器；这不是最终策略动作维度。策略频率以20 Hz为起点，再根据新场景和实物延迟决定。

教师可增加接触和负载编码，学生用历史信息学习控制。完整人类运动参考主要用于奖励与辅助监督，不作为教师每步必须读取的动作剧本。教师与学生使用相同的角度任务接口，学生不读取参考片段编号或仿真接触真值。

所有要输入学生的字段，先检查实物能否取得。若历史信息不足以判断接触，应报告这个限制，并比较增加实际传感反馈的收益。

## 5. 按阶段执行

| 阶段 | 具体要做的事 | 必须产出的东西 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| **P0：建立新的可信基础** | 从原始模型搭建坐姿G29驾驶室、大屏与安装台；检查轮圈碰撞和四种新抓握；再建立新场景的显式控制基线；同时盘点实物接口、行程、负载与延迟 | 可查看场景、几何与接触报告、新控制基线、硬件反馈清单及标定记录 | 布局和接触合理；新基线具备基本可行性；部署输入有真实来源；关键物理参数有实测依据 |
| **P1：建立交互参考** | 采集小批人类示范；验证仿真参考；在实物上检查初始抓握、保持和单手承载 | 数据清单、片段标注、可行参考、实物基础技能记录 | 两方向均有可行参考；实物具备初始支撑和承载条件 |
| **P2：完成180°关键对比** | 比较无参考RL、固定时间参考、允许局部调整的参考；先找出首个失败环节，再扩大训练 | 三组学习曲线、接管窗口误差、承载曲线、失败分类 | 在相同任务下取得完整闭环结果，并能判断参考调整是否产生收益；没有收益就先修改假设 |
| **P3：训练与部署历史学生** | 完成仿真DAgger；实物依次验证小角度、低速接管及180°完整往返；记录首次迁移结果 | 学生模型、仿真与实物对照、真实失败与适配记录 | 学生在仿真和实物上完成180°任务；实物执行不依赖仿真真值 |
| **P4：扩大范围** | 两端逐级扩展连续0–180°目标、360°与540°模板；混入旧任务防止遗忘 | 分角度结果、实物完整长序列、能力回归报告 | 各范围分别完成仿真和实物验收；实物行程不支持的范围单独说明 |
| **P5：论文正式实验** | 冻结方法、模型与协议；完成仿真对照及独立实物会话测试 | 正式表格、视频、失败案例、论文图与可复现配置 | 结论均有对应数据；首次迁移、适配后效果及仿真结果分别报告 |

P0还要核对540°的物理条件：当前G29模型为±450°止挡，即900°总行程。从居中零位单向540°不在这个范围内。先确定真实设备、初始零位和任务角度定义，再决定是否需要别的设备；不能单纯扩大仿真止挡后声称实物支持。

P2先做工程试训，正式方法比较至少使用3个训练种子。根据P0吞吐记录，为各组预先设定相同的交互预算和检查点；报告实际步数、耗时及示范成本。到预算上限仍无改善时，先诊断，不无限追加训练。

### 5.1 实物工作具体怎么做

实物目标是完整展示承载交接与受控回正。小角度跟踪仅作为进入完整任务的步骤。

| 步骤 | 具体操作 | 留下什么证据 |
| --- | --- | --- |
| **R0：测量台架与执行接口** | 确认机器人、灵巧手、被动轮盘及回正负载；标定轮轴坐标、零位、累计角度、物理行程；测反馈频率、动作延迟和驱动误差 | 硬件配置、可用观测字段、负载曲线、时间同步与测量误差 |
| **R1：验证基础接触** | 从有效抓握开始，依次做双手保持、左右单手承载、低速小角度往返；先用显式控制建立可行性依据 | 轮角与驱动轨迹、支撑视频、可行抓点及失败位置 |
| **R2：部署学习策略** | 冻结仿真学生，从±30°、±60°、±90°逐级测试，再做低速交接与±180°完整往返；每一级包含保持和回正 | 首次迁移的全部尝试、交接误差、人工介入次数与原因 |
| **R3：处理真实差异** | 根据失败类型选择模型修正、执行接口修正或真实示范适配；每次只验证一种主要改动 | 使用了多少真实数据、训练成本、适配前后同任务结果 |
| **R4：正式任务与变化测试** | 在支持的机械行程内完成360°／540°及重复往返；改变抓点、可调负载和指令；跨采集会话重复 | 完整任务成功率、误差、长序列漂移、失败案例和连续视频 |

初版在轮轴上配置可同步读取的角度测量，并测量回正负载；各驱动反馈以实际接口为准。若要主张左右手分别承担了多少力矩，需要配置相应的力／力矩测量。没有独立测量时，可以报告轮角、已标定的外部负载和视频中的接触变化，但不能把仿真中的逐手承载曲线当成实物测量。

### 5.2 实物失败后如何适配

先检查坐标、单位、延迟和动作映射。接口正确后，如果主要差异来自摩擦、负载或驱动响应，就用实测值修正仿真及随机化范围，重新训练；如果仍缺少真实接触下的协调，再采集机器人遥操作或人工纠正数据，用BC或带原任务数据约束的微调适配策略。第一版不默认在实物上从零做RL。

真实自主执行日志可以用来诊断和评估，只有包含可靠的专家控制标签时，才直接用于BC。人工干预、辅助支撑和中断均须记录；正式自主任务中发生接管的回合计失败。

首次迁移评估前冻结模型。使用真实轨迹更新策略或仿真后，应标为“真实数据适配后”，再用新会话留出任务评估。正式实物实验至少跨3个采集会话；每个任务组预先固定尝试次数，不只汇报挑选出的成功片段。

## 6. 怎么判断做成了

### 6.1 每条任务必须完整执行

统一执行“转动 → 保持 → 返回零位 → 零位保持”，保持时间先包含3秒和10秒两档。初始参考速度考虑5°/s，需在新场景重新验证，其他速度在物理入口验证后再增加。

名义任务先沿用以下精度目标：运动阶段RMSE不超过1°，每次停止末段3秒的峰值误差不超过1°。全程瞬态峰值另外报告，不能把停止精度写成全程精度。未完成的回合计失败。

每一级正式验收使用预先冻结的案例集，完整任务通过率目标为95%以上，并分别报告左右方向。非法碰撞、真实关节越界、数值或QP硬失败单独列出，不用平均精度抵消。

仿真承载按物理步记录左右手对轮轴的力矩、承载不足的连续时长及其对应误差。实物指标按R0确认的测量条件制定；若轮角噪声或分辨率不足以支持1°门槛，应先完善测量或在实物训练前另定门槛。两端门槛分别冻结，不根据候选结果倒推。

### 6.2 比较什么

- **基线：**在新场景重新建立的显式接管控制器、无参考RL、同专家数据训练的ACT与Diffusion Policy。旧v121只有完成新场景适配与重新验证后，才进入同条件对照。
- **主要消融：**固定时间参考与可调整参考；有无承载项；有无历史记忆。
- **变化条件：**初始抓点、回正负载、摩擦、反馈延迟和有界扰动。
- **泛化：**0–180°内留出部分终点；大角度先报告模板覆盖，不能直接称任意指令泛化。

所有方法使用一致的动作边界、物理模型、任务信息和评价器。分别报告训练、示范生成与交互成本。训练／开发／最终留出按完整轨迹或采集会话划分；用于调参的案例以后只能称回归。

### 6.3 失败后先查什么

| 现象 | 优先检查 |
| --- | --- |
| 物理专家也完成不了 | 姿态可达性、碰撞、抓握和负载是否可行 |
| 专家可行，离线动作损失低，但策略闭环失败 | 标签是否依赖未观测的内部状态；是否覆盖偏离状态 |
| 去程正常，返程或重复操作失效 | 记忆、抓握锚点、预紧是否重复累积；是否缺少返程数据 |
| 教师通过，学生失败 | 特权信息差距、历史长度、学生状态上的标签质量 |
| 单个模板通过，长序列失败 | 状态是否被错误重置，误差与接触变化是否累积 |

## 7. 代码和产物放在哪里

保持现有配置、模型、策略、数据、训练与评价分开的组织方式。需要实现RL时再新增`algorithm/`和`buffer/`，不为每个阶段复制一套项目。

| 路径 | 放什么 |
| --- | --- |
| `humanlike_drive/task/` | 指令、参考匹配、奖励、事件和成功定义 |
| `humanlike_drive/env/`、`controller/` | 场景运行、腕手执行、IK/QP和物理限制 |
| `humanlike_drive/model/`、`policy/` | 编码器、GRU、教师学生和推理接口 |
| `humanlike_drive/dataset/`、`data/` | 数据处理代码，以及按来源划分的数据和清单 |
| 后续`humanlike_drive/algorithm/`、`buffer/` | PPO、蒸馏损失与时序样本缓存 |
| `humanlike_drive/workspace/` | 教师训练、学生训练和基线训练流程 |
| `humanlike_drive/env_runner/` | 同一协议下的冻结策略评价 |
| `humanlike_drive/real_world/` | 实物接口、时钟同步、数据采集、策略部署和中断记录 |
| `data/calibration/`、`data/raw/robot/` | 实测参数、机器人试验、遥操作及人工纠正数据 |
| `docs/experiments/` | 每次试验前写下的变化、预算和通过条件 |
| `outputs/`、`results/` | 原始运行产物，以及精选结论和图表 |

每次运行保留配置、代码版本、种子、数据来源、模型、指标和必要轨迹。局部课程可使用中间状态初始化，最终完整任务验收不能依赖中途重置或辅助支撑。

## 8. 论文最后要回答的三件事

1. **人类交互参考有什么用？**是否降低学习成本、帮助形成有效接管，而不只是让姿态更像人。
2. **为什么允许参考调整？**是否在负载和初态变化时，改善交接承载及角度跟踪。
3. **统一策略实际覆盖什么？**连续角度、典型大角度模板、长序列和实物分别做到什么程度。
